# 岐伯论独立重建｜初读流水线操作说明

本文件说明 `research-rebuild/` 目录下这条"逐篇全量初读 → 机械验收 → 汇总"流水线怎么运行、
每一步产出什么、验收口径是什么、以及哪些事情**不能**由这条流水线代替。

对应提示词：`prompts/deepseek-v4.1-flash-full-reading.md`（系统提示词全文）。
执行代理操作简报：`prompts/initial-reading-brief.md`。

---

## 1. 目标与边界

- 目标：对 `sooon-q9adg-articles-v2.jsonl`（只读语料，4,296 篇，SHA-256
  `E8617186…AAA4`）逐篇建立**可回到原文的证据记录**：问题语境、内容单元、作者主张
  （含归属与语气）、论证推进、概念用法、例证与反驳对象、适用条件、修辞语气、未决问题，
  以及暂定标签。
- 边界：初读**不是**最终分类、不是总论、不是作者自称的统一理论。跨文章归纳一律留给后续研究，
  初读记录中不得写成作者主张（`research_reconstruction` 在初读阶段应尽量不出现，出现即告警）。
- 原始语料只读：任何步骤都不得修改、润色、补全或替换作者原文。

## 3. 一条命令跑一个批次

```bash
cd research-rebuild

# ① 渲染阅读包：打印该批全部文章的提问、正文分段（带 [Pnnn] 与字符范围）、结构、图片清单
python3 scripts/render_batch.py r001-b0001

# ② 填写记录构造器：records/r001-b0001.sessions.py 里的 ANALYSIS
#    （key = records/r001-b0001.skeleton.json 里的 uid；段落号、字符位置、图片由语料机械生成）

# ③ 生成 + 机械验收（内部执行 .sessions.py 并调用校验器）
python3 scripts/build_batch.py r001-b0001
```

`build_batch.py` 退出码 0 且打印 `"status": "PASS"` 即该批完成；输出 `out/r001-b0001.out.jsonl`。
`--check` 只验收不重新生成；若会话构造器或骨架比输出新，会以“输出已过期”失败并提示重建。
`--render` 顺手把阅读包写到 `out/`。

## 4. 全量推进与进度

```bash
# 预处理：为一个或多个批次生成骨架（已全部生成；重复运行只刷新 .skeleton.json，不覆盖已填 ANALYSIS）
python3 scripts/build_sessions.py r001-b0001 r001-b0002

# 全量验收（只验收已有输出的批次，给出 PASS/FAIL/MISSING 汇总）
python3 scripts/validate_all.py

# 汇总为单一记录集（仅在全部批次 PASS 后执行）
python3 scripts/validate_all.py --aggregate      # -> records/reading-records-v2.jsonl

# 进度与状态统计（权威口径）
python3 scripts/update_progress.py               # -> reports/progress.json

# 质量筛检（丰富度分布 + 异常清单：空分析、无主张、needs_reread/blocked 等）
python3 scripts/quality_report.py --out reports/quality-report.json

# 批次调度（按已完成状态生成下一波子代理分配，避免重复处理）
python3 scripts/schedule_batches.py --status
python3 scripts/schedule_batches.py --next --size 3 --waves 12 --prompts
```

## 5. 记录格式（schema 0.2.0）

每篇一行 JSON，顶层字段与系统提示词第 8 节一致：

| 字段 | 生成方式 | 说明 |
| --- | --- | --- |
| `record_type` / `schema_version` | 机械 | `article_reading` / `0.2.0` |
| `corpus_sha256` | 机械 | 与批次一致 |
| `article_id` / `source_ordinal` / `reading_ordinal` | 机械 | 原样回填，不重排 |
| `metadata` | 机械 | 标题、发布时间（+08:00 ISO）、平台、URL |
| `structure.paragraphs` | 机械 | `text` 为权威正文，按 lexical 结构锚定；每段含 `paragraph_id`/`field`/`index`/`char_start`/`char_end` |
| `structure.images` | 机械 | 图片节点（`src` 取自 lexical）；未核验时为 `pending` |
| `structure.lexical` | 机械 | 节点计数、是否存在 text/lexical 差异；差异时附 `text_lexical_divergence` |
| `reading` | 机械 + 阅读者判定 | `status`、`reader_id`、`image_checked`、`batch_id`、起止时间 |
| `analysis` | 阅读者填写 | `question_context`、`content_units`、`main_claims`、`argument_steps`、`concept_usage`、`examples_and_targets`、`conditions`、`rhetoric_and_tone`、`unresolved_questions` |
| `provisional_tags` | 阅读者填写 | `domain/issue/text_function/object_candidates`、`working_keywords`，`status=provisional` |
| `evidence_refs` | 机械封装阅读者提供的短引 | `evidence_id`、`paragraph_id`、`field`、`paragraph_index`、`quote`、`char_start/end`、`relation` |
| `notes` | 阅读者填写 | 缺口、版本差异、平台标签、待外部核查等 |

主张字段：`claim_type` ∈ {author_explicit, author_qualified, author_reported, quoted_or_cited,
opponent_view, research_reconstruction, open_question}；`attribution` ∈ {author, questioner,
cited_source, opponent, unknown}；`modality` ∈ {asserted, qualified, hypothetical, questioned,
negated, predicted}。

## 6. 机械验收口径（`scripts/validate_all.py`）

逐批检查，任一不满足即 FAIL：

1. 行数 = 输入篇数；`article_id` 不重不漏；
2. `record_type`、`schema_version`、`corpus_sha256` 正确；
3. `source_ordinal`、`reading_ordinal`、`title`、`url` 与语料原样一致；
4. `paragraph_id` 不重复、`field` 合法、证据只引用存在的段落/图片；
5. **短引逐字核验**：先比对该记录转录的段落文本，再回查语料原文，不一致即 FAIL；
6. `author_explicit` / `author_qualified` / `author_reported` 主张必须有 `evidence_refs`；
7. `status=read` 必须有 `full_text_checked=true`；有图片的文章必须 `image_checked=true`
   且图片状态不得为 `pending`；
8. `status=blocked|needs_reread` 必须在 `notes` 或 `unresolved_questions` 说明原因；
9. `content_units.paragraph_refs` 必须存在；枚举字段取值合法；`claim.statement` 非空；
10. `reading.batch_id` 与该批一致；`provisional_tags.status=provisional`；
11. 图片存在却标 `not_applicable`、或标 `verified` 但 `image_checked=false` 均 FAIL；
12. 空正文文章不得标 `read`。

告警（不判 FAIL，供复核参考）：`rhetoric_and_tone` 为空、`research_reconstruction` 出现、
主张转述过长、短引超过 200 字、证据无短引且未说明原因。

另有 PowerShell 版验收脚本 `scripts/validate_deepseek_output.ps1`（与 Python 版互为独立实现，
用于交叉验证；已修 UTF-8 读取、`ConvertFrom-Json` 与 `$PID` 只读变量兼容问题）。

## 7. 状态口径（不得混用）

- `text_coverage_complete`：提问、正文、结构已覆盖，且该批通过机械验收；
- `understanding_complete`：`status=read` 且带证据定位的精读记录；
- `needs_reread`：图片未核验、text/lexical 版本差异待复核等；
- `blocked`：无正文或纯图，无法完成初读；
- `independent_review_complete` / `image_review_complete`：独立复核与图像核验，
  **本流水线不产生**，在完成前保持 0。

## 8. 已知限制与人工接管点

1. **图片**：执行代理无图像读取能力。所有含图片的文章一律 `status=needs_reread`、
   `image_checked=false`、图片状态 `pending`，并在 `notes` 与 `unresolved_questions` 说明。
   图片核验需研究者或多模态复核，`image-inventory.csv` 提供 765 个节点的清单。
2. **text 与 lexical 差异**：语料中 `text` 为正文权威来源，`lexical` 结构在少数文章中
   与之不完全一致（含平台话题标签混入、编辑性拼接、追加段落等）。差异一律登记在
   `structure.text_lexical_divergence` 与 `unresolved_questions`，不得据结构补写正文。
   `data/lexical-divergence.csv` 列出 21 篇差量较大的文章。
3. **平台话题标签**：知乎的"科学答集/社科答集/文艺答集/企管答集"等标签出现在 `text` 中，
   属编辑/平台附加文本，作者归属存疑，已在各篇登记，不计入作者主张。
4. **事实断言**：作者文中的人物、事件、数据、文献一律按"文章中的断言"处理，
   需外部核查的一律写入 `unresolved_questions` 并标注"待外部核查"，流水线不代作者下结论。
5. **`brief` 字段**：是正文前约 140 字的去换行截断，只作导航，不得单独支持作者主张。
6. **初读质量**：机械验收保证的是定位、归属字段、格式与短引逐字一致，
   不保证分析判断的完备性；研究者的独立复核仍不可省略（`records/review-records.jsonl`）。
