# 岐伯论 4,305 篇专题化分类框架（v2）

生成日期：2026-09-22

本文是后续全量分类、抽样复核和按专题打印的工作规范。它规定分类的层次、判定顺序、状态字段、抽样方法和交付验收条件；它不修改原始语料，也不把机器候选直接写成岐伯的正式观点。

## 一、这次分类要解决什么问题

当前工作区有两套都很有价值、但回答不同问题的分类：

1. 素问官方分类回答“文章在和谁或什么对象发生什么实践”。快照包含 200 个节点（48 个 `LeoObject`、152 个 `LeoPractice`），根节点为“与自己、与亲族、与友人、与合作者、与社会、与自然、与其它”。它适合做对象—实践导航，但节点之间存在层级重复，同一文章也可能有多个实践边。
2. 第一版及第二版重建使用的 23 个核心概念回答“文章反复处理哪一种跨对象的问题”。它适合跨家庭、职场、国家、技术等对象比较，但关键词候选、宽口径召回和旧版复用不能直接当作唯一专题。

因此不采用“官方节点 = 研究专题”或“23 概念中的 `primary` = 最终主分类”。最终采用四层索引：

```text
一篇文章
  ├─ A. 打印主专题（恰好一个，用于只打印一次和编排目录）
  ├─ B. 打印副专题（零至三个，用于专题交叉阅读）
  ├─ C. 官方对象—实践路径（可多选，保留官方原意）
  └─ D. 岐伯论 23 概念标签（可多选，用于跨文研究）
```

四层还要分别保存自己的审核状态。任何一层的候选状态都不能自动提升其他层的可信度。

## 二、版本和当前覆盖基线

- 当前 v2 语料：4,305 篇，原始 JSONL 只读。
- 第一版已有 4,050 篇的逐篇精读、作者视角证据、论文路由和 23 概念映射；这些结果可以复用作旧文的初始索引，但新目录仍要经过本框架的字段对齐。
- 新增文章：255 篇。DeepSeek 初读覆盖 246 篇，另有 9 篇暂缺初读输出；这 9 篇已有临时人工判断时，只能标为 `manual_provisional`，不能当作已完成独立复核。
- 官方分类快照：官方库存唯一文章 3,698 篇，本地精确命中 3,689 篇；本地语料中 616 篇暂未进入官方库存，238 篇有多个官方分类边；官方树有 12 个空实践节点。

### 主专题的互斥原则

每篇文章最终只能有一个 `primary_print_topic`，以保证打印时文章不会被无意重复。主专题不是“文章提到最多的词”，也不是 23 概念中计数最高的一项。判定优先级为：

1. 正文中作者实际要回答的中心问题或行动场景；
2. 官方对象—实践路径所指向的主要关系对象；
3. 文章中具有连续论证的领域证据；
4. 既有第一版专题论文的明确路由，仅作为旧文的可复用证据，不凌驾于正文。

若两个领域都占据中心位置，选择更能解释文章主要行动建议或冲突的一个作为主专题，另一个写入 `secondary_print_topics`，并在 `classification_note` 说明选择理由。只有在文章确实没有可辨认的中心领域时才进入 A00。

## 四、三套副索引的使用边界

### 1. 官方对象—实践层

保留官方原始路径，例如 `与亲族 / 与子女 / 抚养`，不只保存最后一个叶节点。字段建议为：

- `native_root_names`：一个或多个一级对象；
- `native_object_paths`：对象路径；
- `native_practice_paths`：叶实践路径；
- `native_assignment_status`：官方边的审核状态；
- `native_snapshot_id`：抓取快照和来源页。

本地没有官方边的 616 篇文章不得伪造官方标签。它们仍可进入 A01–A21 或 A00，并将官方层写为 `unassigned`；候选匹配必须另列，不能覆盖原始官方边表。

官方节点允许多标签。比如同一篇文章可以同时位于“与自己 / 与身体 / 了解”和“与合作者 / 与服务者 / 履约”，但打印主专题仍只保留一个。

### 2. 23 个概念层

23 个既有概念名称保持不改：事实与证据、定义与达意、能力与学习、选择与自由、责任与后果、成本与总账、信用与信任、爱与回应、净输出与不掠夺、边界与许可、照料与家庭、劳动与组织、财富与市场、法律与秩序、权力与异议、技术与工程、文明与历史、民族与身份、生态与自然、人工智能与机器、心理与主体、性别与身体、宗教与自然法。

概念标签用于跨文章比较，不用于替代主专题。标签应有正文、提问或已复核证据支持；纯词面命中只能写入候选字段。旧 4,050 篇的完整概念集合可以保留在研究索引，打印封面最多显示一个概念主标签和三个辅助标签，以免目录失去可读性。

### 3. 历时层

发表日期、时期、平台和版本变化是独立字段，不构成另一套互斥专题。需要做历时研究时，从主专题、官方路径或概念标签筛选，再按日期排序。不能因为文章发生在某一时期，就把它自动归入“历史、文明与历时演变”。

## 五、行级字段和状态分离

最终全量索引（建议名称 `article-classification-v2.csv`）至少应包含：

```text
ordinal,id,title,published_at,primary_print_topic,secondary_print_topics,
native_root_names,native_object_paths,native_practice_paths,
native_assignment_status,concept_tags,concept_primary,
classification_status,reading_status,evidence_basis,classification_note,
source_version,snapshot_id
```

三种状态必须分开：

- `classification_status`：`audited`、`manual_confirmed`、`manual_provisional`、`review_required`、`needs_human_classification`、`uncertain`；
- `reading_status`：沿用初读和独立复核的状态，不能用 DeepSeek 输出存在来代替理解完成；
- `native_assignment_status`：`confirmed`、`reassign_needed`、`native_unassigned_valid`、`api_or_version_gap`、`needs_image_review`、`uncertain`。

状态解释：

- `audited`：旧版已有可追溯的研究映射并通过当前机械校验；不等于新官方层已经人工复核。
- `manual_confirmed`：人工回看正文、提问和必要的图片/结构后确认。
- `manual_provisional`：依据原文完成临时补位，但尚未经过规定的独立复核或第二次抽样；也可用于独立复核后中心可辨、但现有专题表缺少合适入口而暂列 A00 的文章。后一情形须在依据中明确写出目录缺口，留待专题边界/注册表审议，不得仅因事实主张未核验而使用临时状态。
- `review_required`：有候选主题但抽样审核尚未完成。
- `needs_human_classification`：最高 cue 过低、最高分并列、证据冲突或跨域边界明显，机器候选不得作为定稿。
- `uncertain`：材料不足、图片未核验或正文不能支持决定。

## 六、抽样、细读和修正流程

抽样不是只抽高频主题，而是按风险分层。固定种子和抽样文件必须写进报告，使后续可以复现。

### 必抽层

1. 新增文章层：255 篇全部进入分类队列；其中 `top_score <= 1`、最高分并列、候选主题跨越 3 个以上主领域、含图片或缺少 DeepSeek 初读的记录全部优先人工回看。
2. 官方覆盖层：每个有文章的官方 `LeoPractice` 至少抽 1 篇；高频节点每个再抽最多 3 篇；官方多标签文章抽 30 篇；官方未命中本地的 616 篇抽约 10%，且不少于 60 篇。
3. 主题边界层：官方节点中旧概念最高占比低于 60% 的节点抽 40 篇；A00 和每个主专题至少抽取一批边界文章。
4. 图像和空正文层：必须在图片实际核验后才能把 `reading_status` 提升为完整；不能把图片标题或链接标题当作正文证据。

### 每篇样本的审阅动作

依次检查原始 question、正文段落、引述块、图片/结构、既有第一版路由和 DeepSeek 证据；再填写：

- 主专题是否保留，若修正则给出新主专题；
- 副专题是否过多、是否有正文支持；
- 官方路径是否确实描述文章实践；
- 23 概念是作者明示、跨文重复，还是仅为检索候选；
- 作者主张、引用观点和研究者重建是否被混写；
- 修正依据的原文段落或短摘录；
- 审核者、日期和结论状态。

机器分类只能生成候选，不能因为候选与官方 `top_old_theme` 一致就自动确认。抽样中发现的系统性问题应先修正规则，再重建全量索引和统计。

## 七、覆盖率和交付验收

最终报告至少要给出以下可核验指标：

1. 语料总行数、唯一 ID、重复 ID、版本哈希；应为 4,305 行且重复 ID 为 0。
2. 主专题覆盖：`primary_print_topic` 非空数量、A00 数量、各专题数量；所有 A01–A21 的文章数和抽样数。
3. 副专题完整性：每个副专题名称均来自注册表，不能出现拼写变体；每篇文章的主专题不应同时出现在副专题中。
4. 官方覆盖：官方库存唯一文章、精确命中、本地未命中、官方多标签文章、空实践节点；逐项与 `native-category-coverage.json` 对账。
5. 概念覆盖：23 个标签的文章数、多标签平均数、无概念标签数；概念统计只能描述研究索引覆盖，不能解释为作者观点强度。
6. 状态分布：`audited`、`manual_confirmed`、`manual_provisional`、`review_required`、`needs_human_classification`、`uncertain` 分开统计；未完成项不得藏在“已分类”总数里。
7. 抽样修正率：按主专题、官方根节点、风险层分别报告同意、改主专题、改副专题、删除候选和无法判断的数量。
8. 可打印性：每篇文章有稳定 `ordinal`、标题、日期、原文 ID、主专题和证据入口；按主专题—日期—ordinal 排序后可以生成不重复的打印包。

正式交付至少包含：

- 全量行级索引（主专题、官方路径、23 概念和三套状态）；
- 官方边表及 616 篇未命中文章的审计清单；
- 主专题注册表和官方—主专题—概念的导航 crosswalk；
- 覆盖率 JSON/Markdown 报告；
- 每个主专题的打印清单和待审清单；
- 本方法文档、固定种子、生成命令和版本快照说明。

- `research-rebuild/reports/article-theme-map-v2.csv` 是旧映射复用加新增候选的研究路由草案，不是最终打印主专题表。
- `research-rebuild/reports/new-theme-stratified-sample.csv` 和 `theme-human-review-queue.csv` 是抽样/人工队列；状态为 `pending`、`review_required` 或 `manual_provisional` 的记录不能在报告中写成“已确认”。
- `research-rebuild/reports/native-article-category-edges.csv` 是官方边表；官方层多标签和本地未命中都应原样保留。
- `research-rebuild/reports/native-theme-crosswalk-200.csv` 是诊断性 crosswalk；其中 `top_old_theme` 只能帮助分层，不能覆盖官方边表或产生唯一主专题。
- `research/data/article_system_concept_map.csv` 和 `article_paper_route_map.csv` 是第一版研究成果的复用入口；正式 v2 索引应保留它们的来源信息，并对新增文章单独记录初读与人工审核状态。

本框架的目标不是制造一个看似整齐但无法追溯的单一标签，而是让 4,305 篇文章在打印时有明确唯一入口，在专题比较时保留多重关系，在官方分类和既有研究不一致时能定位差异并回到原文修正。
