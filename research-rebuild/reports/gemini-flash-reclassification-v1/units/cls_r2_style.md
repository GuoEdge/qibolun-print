# 全书归类复核规范（第二轮：拟移篇目回读全文）

## 输入
`units/cls_r2_in/Mxx.md`。每篇以 `=== 【序号】标题` 开头，下面依次是：
- 现位置：所在单元及其导语
- 拟移至：第一轮建议的目标单元及其导语
- 一轮理由
- 問、答全文

参照 `units/taxonomy.md`，即全书 277 个单元及其导语。

## 判断
必须用 Read 分段读完全文（每段不超过 300 行），逐篇读完「答」，再定去留。
1. 文章的落点（最终在论证什么）在目标单元明显更合适时，判 `move`。
2. 现位置与拟移位置两可，或现位置更合适时，判 `keep`。
3. 两处都不合适、别处明显更合适时，判 `move`，并把 `to` 改成更好的单元。单元名必须与 taxonomy 逐字一致。
4. 宁缺毋滥。第一轮只看了一句主旨，你看的是全文，有权推翻。

## 输出
写入 `units/cls_r2_out/Mxx.json`，块内每篇都必须写：

```json
{"chunk":"M01","items":{"123":{"verdict":"move","to":"B26/性別論戰","why":"≤30字"},"456":{"verdict":"keep","why":"≤30字"}}}
```

## 自检
用 `/data/service/hnp/bin/python3 -c` 内联执行。/tmp 只读；shell 的 getcwd 会报错，一律用绝对路径。
- 键集合与 md 中全部【序号】一致。
- verdict 只取 move 或 keep。
- move 的 to 在 taxonomy 中存在，且不等于现位置。

只写 JSON，不要在 units 目录留下其他文件。

## 回报
每块报：篇数，move 几篇，keep 几篇，改了 to 的几篇。
